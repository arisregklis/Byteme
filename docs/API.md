# API – v2 — 23/11/2026

## Διεπαφές REST των τεσσάρων συστημάτων

Το παρόν έγγραφο περιγράφει τις διεπαφές REST μεταξύ:

1. Του Πληκτρολογίου Χρήστη – Kiosk.
2. Του Κεντρικού Συστήματος.
3. Του Συστήματος Ελέγχου Ανελκυστήρα.
4. Του Συστήματος Αξιολόγησης.

Αλλαγές από την έκδοση v1: ακριβή endpoints, πλήρη URLs, κωδικοί απάντησης και παραδείγματα JSON.

## 0. Γενικά

- Πρωτόκολλο επικοινωνίας: HTTP.
- Μορφή δεδομένων: JSON.
- Κωδικοποίηση χαρακτήρων: UTF-8.
- Όλα τα requests και responses που περιέχουν JSON χρησιμοποιούν `Content-Type: application/json; charset=UTF-8`.
- Η ένδειξη v2 αφορά την έκδοση του εγγράφου API.
- Τα URLs δεν περιλαμβάνουν version prefix.

### 0.1 Κανόνες ορόφων

- Το σύστημα υποστηρίζει κτίρια με 3 έως 200 ορόφους.
- Αν το κτίριο έχει `N` ορόφους, οι έγκυροι όροφοι είναι από `0` έως `N-1`.
- Ο όροφος `0` θεωρείται το ισόγειο.
- Ο όροφος αφετηρίας ονομάζεται `source_floor`.
- Ο όροφος προορισμού ονομάζεται `destination_floor`.
- Τα `source_floor` και `destination_floor` είναι ακέραιοι αριθμοί.
- Όροφος μικρότερος από `0` ή μεγαλύτερος από `N-1` απορρίπτεται με `400 Bad Request`.
- Ο `destination_floor` δεν επιτρέπεται να είναι ίδιος με τον `source_floor`.

### 0.2 Κανόνες ανελκυστήρων

- Το σύστημα υποστηρίζει από 2 έως 20 ανελκυστήρες.
- Κάθε ανελκυστήρας έχει μοναδικό `elevator_id`.
- Το `elevator_id` είναι κεφαλαίο λατινικό γράμμα από `A` έως `T`.
- Δεν επιτρέπεται να υπάρχουν δύο ανελκυστήρες με το ίδιο `elevator_id`.
- Άγνωστο αλλά συντακτικά έγκυρο `elevator_id` επιστρέφει `404 Not Found`.
- Μη έγκυρο αναγνωριστικό, όπως `"c"`, `"AA"` ή `"1"`, επιστρέφει `400 Bad Request`.

### 0.3 Διευθύνσεις και προεπιλεγμένες θύρες

- Τα υποσυστήματα εκτελούνται αρχικά στον ίδιο υπολογιστή και χρησιμοποιούν το `localhost`.
- Κάθε υποσύστημα χρησιμοποιεί διαφορετική θύρα HTTP.
- Οι θύρες μπορούν να αλλάξουν μέσω παραμέτρων εκκίνησης.
- Η γενική μορφή μιας διεύθυνσης είναι `http://localhost:<port>/<endpoint>`.

### 0.4 Κωδικοί HTTP

| Κωδικός | Ονομασία | Πότε χρησιμοποιείται |
|---:|---|---|
| `200 OK` | Επιτυχία | Το αίτημα ολοκληρώθηκε επιτυχώς |
| `202 Accepted` | Έγινε αποδεκτό | Το αίτημα έγινε δεκτό και η επεξεργασία συνεχίζεται |
| `400 Bad Request` | Λάθος αίτημα | Άκυρο JSON, λάθος τύπος ή άκυρη τιμή |
| `404 Not Found` | Δεν βρέθηκε | Άγνωστο ID ή endpoint |
| `405 Method Not Allowed` | Μη επιτρεπτή μέθοδος | Χρησιμοποιήθηκε λάθος HTTP method |
| `409 Conflict` | Σύγκρουση κατάστασης | Η εντολή δεν επιτρέπεται στην τρέχουσα κατάσταση |
| `500 Internal Server Error` | Εσωτερικό σφάλμα | Απρόβλεπτο σφάλμα του υποσυστήματος |
| `503 Service Unavailable` | Μη διαθέσιμη υπηρεσία | Απαραίτητο υποσύστημα δεν λειτουργεί ή δεν απαντά |

### 0.5 Μορφή απάντησης σφάλματος

Όλα τα υποσυστήματα χρησιμοποιούν κοινή μορφή JSON για τα σφάλματα.

| Πεδίο | Τύπος | Υποχρεωτικό | Περιγραφή |
|---|---|---|---|
| `code` | string | Ναι | Σύντομος κωδικός σφάλματος |
| `message` | string | Ναι | Κατανοητή περιγραφή |
| `request_id` | string | Όχι | Το σχετικό αίτημα |
| `timestamp` | string | Ναι | Χρόνος σε UTC και ISO-8601 |

Παράδειγμα:

```json
{
  "code": "INVALID_FLOOR",
  "message": "Floor must be between 0 and 49",
  "timestamp": "2026-11-23T18:30:00Z"
}
```

## 1. Αρχιτεκτονική και συνολική ροή

Το σύστημα αποτελείται από τέσσερις ανεξάρτητες εφαρμογές Java.

### 1.1 Πληκτρολόγιο χρήστη

Το Kiosk:

- Γνωρίζει τον όροφο εγκατάστασής του.
- Δέχεται τον όροφο προορισμού.
- Στέλνει αίτημα στο Κεντρικό Σύστημα.
- Δέχεται το επιλεγμένο `elevator_id` μέσω `POST /display`.
- Εμφανίζει το γράμμα στον χρήστη.

### 1.2 Κεντρικό σύστημα

Το Κεντρικό:

- Δέχεται αιτήματα διαδρομών.
- Διαβάζει την κατάσταση των ανελκυστήρων.
- Επιλέγει τον καταλληλότερο ανελκυστήρα.
- Στέλνει στάσεις.
- Ενημερώνει το Kiosk.

### 1.3 Σύστημα ελέγχου ανελκυστήρα

Ο ελεγκτής ανελκυστήρα:

- Δέχεται στάσεις και εντολές.
- Διατηρεί την κατάσταση και τις επόμενες στάσεις.
- Ελέγχει κινητήρα, θύρες και αισθητήρες.
- Εφαρμόζει τους κανόνες ασφαλείας.
- Στέλνει γεγονότα στην Αξιολόγηση.

### 1.4 Σύστημα αξιολόγησης

Η Αξιολόγηση:

- Δημιουργεί δοκιμαστικά αιτήματα.
- Εκτελεί σενάρια.
- Λαμβάνει γεγονότα.
- Υπολογίζει μετρικές.
- Εμφανίζει αποτελέσματα.

### 1.5 Συνολική ροή

1. Ο χρήστης εισάγει προορισμό στο Kiosk.
2. Το Kiosk στέλνει `POST /requests`.
3. Το Κεντρικό ελέγχει το αίτημα (400 ή 409 αν είναι άκυρο)
4. Καλεί GET /state στους ανελκυστήρες. 
5. Επιλέγει τον καταλληλότερο ανελκυστήρα (503 αν κανένας)
 6. Επιστρέφει 202 Accepted.
 7. Στέλνει τις στάσεις μέσω POST /stops και ενημερώνει το Kiosk μέσω POST /display.
8. Ο ανελκυστήρας εκτελεί τη διαδρομή.
9. Ο ανελκυστήρας στέλνει γεγονότα μέσω `POST /events`.
10. Η Αξιολόγηση υπολογίζει τα αποτελέσματα.

## 2. Κεντρικό σύστημα

Το Κεντρικό Σύστημα εκτελείται από τη γραμμή εντολών και ακούει προεπιλεγμένα στη θύρα `3000`.

Βασικές ευθύνες:

- Δέχεται αιτήματα διαδρομών.
- Παρακολουθεί την κατάσταση των ανελκυστήρων.
- Επιλέγει τον καταλληλότερο ανελκυστήρα.
- Στέλνει τις απαραίτητες στάσεις.
- Ενημερώνει το Kiosk.
- Διαχειρίζεται τη διαμόρφωση του κτιρίου.

### 2.1 `POST /requests`

Δέχεται νέο αίτημα διαδρομής από το Kiosk ή το Σύστημα Αξιολόγησης.

URL:

```text
POST http://localhost:3000/requests
```

| Πεδίο | Τύπος | Υποχρεωτικό | Περιγραφή |
|---|---|---|---|
| `request_id` | string | Ναι | Μοναδικό ID αιτήματος |
| `source_floor` | integer | Ναι | Όροφος αφετηρίας |
| `destination_floor` | integer | Ναι | Όροφος προορισμού |
| `callback_url` | string | Μόνο για Kiosk | URL του `POST /display` |

Το `callback_url` είναι υποχρεωτικό για αίτημα από Kiosk και προαιρετικό για αίτημα από το Σύστημα Αξιολόγησης.

Παράδειγμα:

```json
{
  "request_id": "req-41",
  "source_floor": 2,
  "destination_floor": 8,
  "callback_url": "http://localhost:3100/display"
}
```

Επιτυχής απάντηση `202 Accepted`:

```json
{
  "request_id": "req-41",
  "status": "PENDING"
}
```

Στη συνέχεια το Κεντρικό:
1. Ελέγχει request_id, ορόφους και callback_url (400 / 409) 
2. Ζητά GET /state από όλους τους ανελκυστήρες. 
3. Επιλέγει ανελκυστήρα (503 αν κανένας).  
4. Απαντά 202 Accepted. 
5. Στέλνει δύο POST /stops (PICKUP στο source_floor, DROPOFF στο destination_floor). 
6. Αν υπάρχει callback_url, στέλνει POST /display.

Πιθανά σφάλματα:

| Κωδικός | Αιτία |
|---:|---|
| `400 Bad Request` | MISSING_REQUEST_ID, INVALID_FLOOR, SAME_FLOOR, INVALID_CALLBACK_URL, BAD_REQUEST (άκυρο JSON) |
| `409 Conflict` | DUPLICATE_REQUEST: το request_id έχει ήδη πάρει 202. Μετά από 503 μπορεί να ξανασταλεί |
| `503 Service Unavailable` | Δεν υπάρχει διαθέσιμος ανελκυστήρας  - NO_ELEVATOR_AVAILABLE|

### 2.2 `GET /elevators`

Επιστρέφει την κατάσταση όλων των ανελκυστήρων.

URL:

```text
GET http://localhost:3000/elevators
```

Παράδειγμα απάντησης `200 OK`:

```json
{
  "elevators": [
    {
      "elevator_id": "A",
      "floor": 0,
      "direction": "NONE",
      "status": "IDLE"
    },
    {
      "elevator_id": "C",
      "error": "unreachable"
    }
  ]
}
```

Αν ένας ανελκυστήρας δεν απαντά σε 3 δευτερόλεπτα, εμφανίζεται με "error": "unreachable" και στην επιλογή ανελκυστήρα μετράει ως OUT_OF_SERVICE. Για κάθε ανελκυστήρα επιστρέφεται ολόκληρο το JSON του GET /state (§3.1)..

### 3.2 `POST /stops`

Προσθέτει μία νέα στάση.

URL:

```text
POST http://localhost:3003/stops
```

Παράδειγμα αιτήματος:

```json
{
  "request_id": "req-41",
  "floor": 2,
  "type": "PICKUP"
}
```

Απάντηση `200 OK`:

```json
{
  "accepted": true,
  "next_stops": [2]
}
```

Αν η στάση υπάρχει ήδη, δεν προστίθεται δεύτερη φορά.

Πιθανά σφάλματα:

- `400 Bad Request` για άκυρο όροφο ή τύπο στάσης.
- `409 Conflict` αν ο ανελκυστήρας είναι `STOPPED`, `EMERGENCY` ή `OUT_OF_SERVICE`.

Απάντηση `200 OK`:

```json
{
  "elevator_id": "C",
  "status": "STOPPED"
}
```

Αν είναι ήδη σταματημένος, επιστρέφεται `409 Conflict`.

### 3.4 `POST /resume`

Συνεχίζει τη λειτουργία μετά από `POST /stop`.

URL:

```text
POST http://localhost:3003/resume
```

Απάντηση `200 OK`:

```json
{
  "elevator_id": "C",
  "status": "IDLE"
}
```

Επιστρέφεται `409 Conflict` όταν:

- Ο ανελκυστήρας δεν είναι `STOPPED`.
- Οι θύρες δεν είναι ασφαλισμένες.
- Υπάρχει υπέρβαρο.
- Υπάρχει emergency ή βλάβη.

## 4. Πληκτρολόγιο χρήστη

Το Kiosk εκτελείται από τη γραμμή εντολών.

Παράδειγμα εκκίνησης:

```text
--floor 2 --port 3100 --central-url http://localhost:3000 --floor 10
```

Το Kiosk:

- Γνωρίζει τον όροφο εγκατάστασής του.
- Δέχεται τον όροφο προορισμού.
- Ελέγχει αν ο προορισμός είναι έγκυρος.
- Στέλνει το αίτημα στο Κεντρικό.
- Εμφανίζει το γράμμα του ανελκυστήρα.

### 4.1 Αποστολή αιτήματος

Το Kiosk στέλνει `POST /requests` στο Κεντρικό.

Παράδειγμα:

```json
{
"request_id": "req-2-1",
  "source_floor": 2,
  "destination_floor": 8,
  "callback_url": "http://localhost:3100/display"
}
```

Αν το Κεντρικό δεν απαντά, το Kiosk εμφανίζει κατάλληλο μήνυμα σφάλματος.

### 4.2 `POST /display`

Καλείται από το Κεντρικό όταν επιλεγεί ανελκυστήρας.

URL:

```text
POST http://localhost:3100/display
```

Παράδειγμα αιτήματος:

```json
{
  "request_id": "req-41",
  "elevator_id": "C"
}
```

Απάντηση `200 OK`:

```json
{
  "shown": true
}
```

Το Kiosk εμφανίζει:

```text
Χρησιμοποιήστε τον ανελκυστήρα C
```

Επιστρέφεται:

- `400 Bad Request` για άκυρο `elevator_id`.
- `404 Not Found` για άγνωστο `request_id`.
