# Σύστημα Δοκιμών και Αξιολόγησης

## 1. Σκοπός

Το Σύστημα Αξιολόγησης είναι υπεύθυνο για τον έλεγχο της συνολικής λειτουργίας του συστήματος έξυπνων ανελκυστήρων.

Δημιουργεί εικονικά αιτήματα χρηστών, τα στέλνει στο Κεντρικό Σύστημα και λαμβάνει γεγονότα από τους ανελκυστήρες. Με βάση αυτά τα στοιχεία υπολογίζει μετρικές, όπως ο χρόνος αναμονής, ο χρόνος διαδρομής και το ποσοστό επιτυχίας των αιτημάτων.

Οι βασικές λειτουργίες του είναι:

- Δημιουργία σεναρίων λειτουργίας.
- Δημιουργία εικονικών αιτημάτων χρηστών.
- Αποστολή αιτημάτων στο Κεντρικό Σύστημα.
- Λήψη γεγονότων από τους ανελκυστήρες.
- Καταγραφή της εξέλιξης κάθε αιτήματος.
- Υπολογισμός μετρικών απόδοσης.
- Καταγραφή σφαλμάτων και γεγονότων ασφαλείας.
- Εμφάνιση των τελικών αποτελεσμάτων.

---

## 2. Επικοινωνία με τα άλλα συστήματα

Η βασική ροή είναι:

```text
Σύστημα Αξιολόγησης
        |
        | POST /requests
        v
Κεντρικό Σύστημα
        |
        | POST /stops
        v
Σύστημα Ελέγχου Ανελκυστήρα
        |
        | POST /events
        v
Σύστημα Αξιολόγησης
```

Το Σύστημα Αξιολόγησης:

- Στέλνει εικονικά αιτήματα στο Κεντρικό Σύστημα.
- Μπορεί να ζητά την κατάσταση όλων των ανελκυστήρων.
- Δέχεται γεγονότα από τους ανελκυστήρες.
- Συνδέει τα γεγονότα με το αντίστοιχο `request_id`.
- Υπολογίζει τα αποτελέσματα της δοκιμής.

## 3. Εκκίνηση

Το πρόγραμμα εκτελείται από τη γραμμή εντολών.

Παράδειγμα:

```bash
java -jar evaluation-system.jar \
  --port 8300 \
  --central-url http://localhost:3000
```

Οι βασικές παράμετροι είναι:

| Παράμετρος | Παράδειγμα | Σημασία |
|---|---|---|
| `--port` | `8300` | Θύρα του Συστήματος Αξιολόγησης |
| `--central-url` | `http://localhost:3000` | Διεύθυνση Κεντρικού Συστήματος |
| `--scenario` | `uniform` | Σενάριο δοκιμής |
| `--requests` | `100` | Πλήθος αιτημάτων |
| `--duration-seconds` | `300` | Διάρκεια δοκιμής |
| `--seed` | `42` | Τιμή επαναληψιμότητας |

Παράδειγμα:

```bash
java -jar evaluation-system.jar \
  --port 8300 \
  --central-url http://localhost:3000 \
  --scenario morning_rush \
  --requests 100 \
  --duration-seconds 300 \
  --seed 42
```

## 4. Σενάρια αξιολόγησης

### 4.1 Uniform

Στο σενάριο `uniform`:

- Ο όροφος αφετηρίας επιλέγεται τυχαία.
- Ο όροφος προορισμού επιλέγεται τυχαία.
- Όλοι οι όροφοι έχουν περίπου την ίδια πιθανότητα επιλογής.
- Ο όροφος αφετηρίας πρέπει να είναι διαφορετικός από τον προορισμό.

Παράδειγμα:

```text
3 → 12
8 → 1
0 → 6
```

### 4.2 Morning rush

Στο `morning_rush` οι περισσότεροι χρήστες ξεκινούν από το ισόγειο και μετακινούνται προς υψηλότερους ορόφους.

Παράδειγμα:

```text
0 → 5
0 → 12
0 → 8
0 → 17
```

### 4.3 Evening rush

Στο `evening_rush` οι περισσότεροι χρήστες ξεκινούν από διαφορετικούς ορόφους και κατευθύνονται προς το ισόγειο.

Παράδειγμα:

```text
15 → 0
7 → 0
12 → 0
4 → 0
```

### 4.4 Προαιρετικά σενάρια

Αργότερα μπορούν να προστεθούν:

- Πολλά ταυτόχρονα αιτήματα.
- Ένας ανελκυστήρας εκτός λειτουργίας.
- Ανοιχτή ή μπλοκαρισμένη πόρτα.
- Υπέρβαση βάρους.
- Διακοπή ρεύματος.
- Κατάσταση έκτακτης ανάγκης.
- Απότομη πτώση πίεσης σε υδραυλικό ανελκυστήρα.

## 5. Επαναληψιμότητα

Κάθε σενάριο δέχεται μία τιμή `seed`.

Αν χρησιμοποιηθούν:

- Το ίδιο scenario.
- Το ίδιο seed.
- Το ίδιο πλήθος ορόφων.
- Το ίδιο πλήθος αιτημάτων.

τότε δημιουργούνται τα ίδια αιτήματα με την ίδια σειρά.

Έτσι μπορούμε να συγκρίνουμε διαφορετικές εκδόσεις του αλγορίθμου κάτω από τις ίδιες συνθήκες.

## 6. Καταστάσεις ενός run

```java
public enum RunStatus {
    CREATED,
    RUNNING,
    COMPLETED,
    FAILED,
    CANCELLED
}
```

| Κατάσταση | Σημασία |
|---|---|
| `CREATED` | Το run δημιουργήθηκε |
| `RUNNING` | Η δοκιμή εκτελείται |
| `COMPLETED` | Η δοκιμή ολοκληρώθηκε |
| `FAILED` | Παρουσιάστηκε σοβαρό σφάλμα |
| `CANCELLED` | Η δοκιμή ακυρώθηκε |

Κάθε run έχει μοναδικό `run_id`.

Παράδειγμα:

```text
run-001
```

- `pickup_at`

## 8. Μετρικές

### Χρόνος ανάθεσης

```text
assignment_time = assigned_at - created_at
```

### Χρόνος αναμονής

```text
waiting_time = pickup_at - created_at
```

### Χρόνος διαδρομής

```text
travel_time = dropoff_at - pickup_at
```

### Συνολικός χρόνος εξυπηρέτησης

```text
total_service_time = dropoff_at - created_at
```

### Μέσος χρόνος αναμονής

```text
average_waiting_time =
άθροισμα χρόνων αναμονής / ολοκληρωμένα αιτήματα
```

### Μέσος χρόνος διαδρομής

```text
average_travel_time =
άθροισμα χρόνων διαδρομής / ολοκληρωμένα αιτήματα
```

### Ποσοστό επιτυχίας

```text
success_rate =
ολοκληρωμένα αιτήματα / συνολικά αιτήματα × 100
```

### Throughput

```text
throughput =
ολοκληρωμένα αιτήματα / διάρκεια δοκιμής σε λεπτά
```

Θα καταγράφονται επίσης:

- Μέγιστος χρόνος αναμονής.
- Πλήθος αποτυχημένων αιτημάτων.
- Αιτήματα ανά ανελκυστήρα.
- Στάσεις ανά ανελκυστήρα.
- Όροφοι που διένυσε κάθε ανελκυστήρας.
- Γεγονότα ασφαλείας.

## 9. POST /runs

Δημιουργεί και ξεκινά ένα νέο run.

```http
POST http://localhost:8300/runs
Content-Type: application/json
```

Request:

```json
{
  "scenario": "uniform",
  "request_count": 100,
  "duration_seconds": 300,
  "seed": 42,
  "floors": 20,
  "elevators": 4
}
```

Απάντηση:

```http
202 Accepted
```

```json
{
  "run_id": "run-001",
  "status": "RUNNING",
  "scenario": "uniform",
  "request_count": 100,
  "seed": 42
}
```

Άγνωστο scenario:

```http
400 Bad Request
```

```json
{
  "error": "unknown scenario"
}
```

Αν το Κεντρικό Σύστημα δεν είναι διαθέσιμο:

```http
503 Service Unavailable
```

```json
{
  "error": "central system is unavailable"
}
```

## 13. Γεγονότα ανελκυστήρα

Τα βασικά events είναι:

| Event | Σημασία |
|---|---|
| `STOP_ASSIGNED` | Προστέθηκε στάση |
| `MOVEMENT_STARTED` | Ξεκίνησε η κίνηση |
| `FLOOR_PASSED` | Πέρασε από έναν όροφο |
| `PICKUP_COMPLETED` | Παραλήφθηκε ο χρήστης |
| `DROPOFF_COMPLETED` | Ολοκληρώθηκε η διαδρομή |
| `DOORS_OPENED` | Άνοιξαν οι θύρες |
| `DOORS_CLOSED` | Έκλεισαν οι θύρες |
| `STOPPED` | Σταμάτησε ο ανελκυστήρας |
| `RESUMED` | Επανήλθε σε λειτουργία |
| `OVERLOAD` | Εντοπίστηκε υπερφόρτωση |
| `DOOR_BLOCKED` | Εντοπίστηκε εμπόδιο |
| `EMERGENCY` | Ενεργοποιήθηκε έκτακτη ανάγκη |
| `POWER_FAILURE` | Διακόπηκε η τροφοδοσία |
| `OUT_OF_SERVICE` | Τέθηκε εκτός λειτουργίας |
| `HYDRAULIC_PRESSURE_DROP` | Εντοπίστηκε πτώση πίεσης |

Το `PICKUP_COMPLETED` χρησιμοποιείται για τον χρόνο αναμονής και το `DROPOFF_COMPLETED` για τον χρόνο διαδρομής.

## 16. Έλεγχος λανθασμένων δεδομένων

Το σύστημα πρέπει να απορρίπτει:

- Άγνωστο scenario.
- Αρνητικό ή μηδενικό πλήθος αιτημάτων.
- Άκυρο `run_id`.
- Άκυρο `request_id`.
- Άγνωστο event.
- Όροφο εκτός ορίων.
- Ίδιο όροφο αφετηρίας και προορισμού.
- `DROPOFF_COMPLETED` πριν από `PICKUP_COMPLETED`.
- Χρονική στιγμή ολοκλήρωσης πριν από τη δημιουργία του αιτήματος.

Κοινή μορφή σφάλματος:

```json
{
  "error": "invalid event sequence"
}
```

## 18. JUnit tests

Οι βασικοί έλεγχοι είναι:

1. Το `uniform` δημιουργεί τον σωστό αριθμό αιτημάτων.
2. Οι όροφοι είναι μέσα στα επιτρεπόμενα όρια.
3. Η αφετηρία διαφέρει από τον προορισμό.
4. Το ίδιο seed δημιουργεί τα ίδια αιτήματα.
5. Ο χρόνος αναμονής υπολογίζεται σωστά.
6. Ο χρόνος διαδρομής υπολογίζεται σωστά.
7. Το ποσοστό επιτυχίας υπολογίζεται σωστά.
8. Το `POST /runs` δέχεται έγκυρα δεδομένα.
9. Το `POST /events` απορρίπτει άκυρο event.
10. Άγνωστο `run_id` επιστρέφει `404`.
11. Διπλό event δεν υπολογίζεται δεύτερη φορά.
12. Το dropoff πριν από το pickup απορρίπτεται.
13. Τα αποτυχημένα αιτήματα δεν μπαίνουν στον μέσο χρόνο αναμονής.
14. Ένα event ασφαλείας αυξάνει τον σωστό μετρητή.

## 19. Αυτόνομη ανάπτυξη

Το Σύστημα Αξιολόγησης μπορεί να αναπτυχθεί χωρίς να λειτουργεί ακόμη το Κεντρικό Σύστημα.

Για αυτό μπορεί να χρησιμοποιηθεί ένα `FakeCentralClient`:

```java
public class FakeCentralClient implements CentralClient {

    @Override
    public AssignmentResponse sendRequest(GeneratedRequest request) {
        return new AssignmentResponse(
                request.getRequestId(),
                "A",
                "ASSIGNED"
        );
    }
}
```

Με αυτό μπορούμε να ελέγξουμε:

- Τη δημιουργία των σεναρίων.
- Την επαναληψιμότητα του seed.
- Την αποθήκευση των events.
- Τον υπολογισμό των μετρικών.
- Τα REST endpoints.
- Την εμφάνιση των αποτελεσμάτων.

Αργότερα το `FakeCentralClient` θα αντικατασταθεί από το πραγματικό `HttpCentralClient`.

## 20. Πρώτη λειτουργική έκδοση

Η πρώτη έκδοση πρέπει να περιλαμβάνει:

- Εκκίνηση στη θύρα `8300`.
- `POST /runs`.
- `POST /events`.
- `GET /results/{run_id}`.
- Την interface `Scenario`.
- Το `UniformScenario`.
- Δημιουργία αιτημάτων με seed.
- Αποθήκευση δεδομένων στη μνήμη.
- Υπολογισμό μέσου χρόνου αναμονής.
- Υπολογισμό μέσου χρόνου διαδρομής.
- Υπολογισμό επιτυχημένων και αποτυχημένων αιτημάτων.
- Εμφάνιση αποτελεσμάτων.
- Αρχικά JUnit tests.
- Επιτυχή δόμηση με Maven.

Για την πρώτη παρουσίαση τα endpoints μπορούν να επιστρέφουν προσωρινά σταθερά JSON, αρκεί να αναφέρεται ότι πρόκειται για αρχικό stub.

## 21. Περιορισμοί αρχικής έκδοσης

Στην αρχική έκδοση:

- Τα δεδομένα αποθηκεύονται μόνο στη μνήμη.
- Τα αποτελέσματα χάνονται όταν σταματήσει το πρόγραμμα.
- Δεν υπάρχει γραφική διεπαφή.
- Οι χρόνοι προέρχονται από προσομοίωση.
- Δεν γίνεται πραγματική μέτρηση κατανάλωσης ενέργειας.
- Μπορεί αρχικά να υποστηρίζεται μόνο το `uniform`.
- Ορισμένα events μπορούν να δημιουργούνται τεχνητά για δοκιμές.
- Τα σενάρια βλαβών μπορούν να προστεθούν αργότερα.

## 22. Κριτήρια ολοκλήρωσης

Το αρχικό Σύστημα Αξιολόγησης θεωρείται λειτουργικό όταν:

- Ξεκινά από τη γραμμή εντολών.
- Ακούει στη θύρα `8300`.
- Δημιουργεί ένα run.
- Δημιουργεί έγκυρα αιτήματα.
- Το ίδιο seed δίνει τα ίδια αιτήματα.
- Δέχεται events από ανελκυστήρες.
- Συνδέει τα events με τα σωστά αιτήματα.
- Υπολογίζει χρόνο αναμονής.
- Υπολογίζει χρόνο διαδρομής.
- Υπολογίζει ποσοστό επιτυχίας.
- Επιστρέφει αποτελέσματα σε JSON.
- Αντιμετωπίζει άκυρα δεδομένα.
- Περνούν τα βασικά JUnit tests.
- Το project μεταγλωττίζεται με Maven.
- Η υλοποίηση συμφωνεί με το `API.md`.
